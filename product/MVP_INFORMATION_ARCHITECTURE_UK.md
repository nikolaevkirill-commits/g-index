# Інформаційна архітектура MVP

Дата: 2026-08-12. Це канон для mobile/Play companion; production dashboard не змінюється цим документом.

## Нижня навігація

1. **Сьогодні** — один operational state, причина, age, наступна зміна.
2. **Час** — найближчі часові вікна та 3/27-денний контекст.
3. **Небо** — космічна погода, Місяць, затемнення, планети, зближення, видимість.
4. **Jyotish** — традиційний індійський календар, локальні вікна й пояснення факторів.
5. **Ви** — активність, персональний шар, журнал і налаштування; Formula Audit лишається технічним другим рівнем.

## Екран «Сьогодні»

Порядок зверху вниз:

1. Один hero-state: `ACT / CAUTION / HOLD / UNKNOWN`.
2. Людська причина без термінів формули.
3. Provenance strip: тип даних, source, observed/generated time, age, confidence.
4. Найближча зміна з абсолютним локальним часом.
5. Три компактні картки: Космічна погода / Події неба / Jyotish.
6. «Чому?» — внески факторів, без другого verdict.

`UNKNOWN` використовується fail-closed, коли даних недостатньо або конфлікт неможливо розв’язати. Він не фарбується зеленим.

## Незалежні кольорові канали

- **Decision color:** тільки `ACT/CAUTION/HOLD/UNKNOWN`.
- **Freshness badge:** `LIVE/DELAYED/LAST_GOOD/STALE` і ніколи не означає дозвіл.
- **Layer badge:** `OBSERVED/FORECAST/REFERENCE/CALENDAR/RESEARCH`.
- **Event visibility:** visible/low/not visible/unknown — не verdict дня.

Картка джерела може мати зелений індикатор доступності, але її фон і текст не можуть виглядати як позитивне operational-рішення.

## Подія неба

Кожна картка містить:

- назву й тип фізичної події;
- початок/пік/кінець у локальному часі;
- локацію та timezone, для яких обчислена видимість;
- перелік тіл і критерій видимості для «параду»;
- джерело ефемерид і час розрахунку;
- явний `score_effect`, за замовчуванням `0`.

## Jyotish і Panchanga

`Jyotish` — назва продуктового розділу. `Panchanga` — його календарний підрозділ, а не назва всього продукту й не окремий прогноз. На простому рівні: один традиційний summary і найближче релевантне вікно. У деталях: Tithi, Vara, Nakshatra, Yoga, Karana, Rahu/Yama/Gulika з локальними межами. Усі складові формують один агрегований компонент `P`; UI не створює п’ять додаткових голосів.

## Сповіщення

Кожне правило має `type`, `threshold`, `lead_minutes`, `quiet_hours`, `enabled` і source scope. Повідомлення каже, чи подія спостережена або прогнозована. Safety-alert і provenance безкоштовні; custom rules можуть бути paid лише пізніше.

## Accessibility

- зміст не кодується лише кольором;
- minimum touch target 48×48 dp;
- масштаб тексту 200% не приховує timestamp/source;
- screen-reader label читає state, причину, age і наступну зміну одним логічним блоком;
- анімація не потрібна для розуміння зміни стану.
